# Privacy / Privacidad
Keep real sessions, reports, checkpoints and personalized source files outside the repository, preferably in a private local folder. Only empty templates and synthetic examples belong in Git. The build uses explicit file allowlists and rejects nonempty continuity/progress logs using baseline hashes. A preventive privacy checker scans tracked files and built packages for email addresses, credential-like patterns, local user paths, risky filenames and JPEG application metadata. It does not scan all historical objects, image pixels or all personal data; manually review before pushing. `.gitignore` does not remove already tracked files or Git history. If sensitive content has been committed, stop publication, remove it from history where appropriate and rotate exposed secrets. No analytics data is uploaded by the local Python tool. Avoid public GitHub issues containing transcripts or personal identifiers. ChatGPT data handling depends on account settings and OpenAI terms.

## Maintainer Git identity
Use a repository-local Git identity with a GitHub-provided noreply address. Verify both author and committer before publishing. Inspect all reachable refs, workflow logs and old commit references; rewriting a branch does not guarantee removal from GitHub caches or retained objects. If old sensitive metadata may remain, consider a fresh repository with clean history or request help from GitHub Support before making the project public. Do not copy private records into tracked state templates.

## Website and build artifacts
The installation guide stores only manually checked setup steps in browser local storage, where available. Reset progress clears those steps. It does not implement tracking or transmit conversations. Hosting and linked services have their own privacy practices. Public-repository Actions artifacts are not private; only synthetic/public-ready materials may be uploaded. See SECURITY.md for reporting.
